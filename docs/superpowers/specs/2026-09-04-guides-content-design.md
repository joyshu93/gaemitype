# 개미타입 가이드 콘텐츠 설계

## 목표

개미타입의 4축·16타입 구조를 사용자가 더 정확하게 이해하고 결과를 자기점검에 활용할 수 있도록, 독창적이고 완결된 가이드 콘텐츠 3개를 제공한다. 이전 AdSense 심사에서 지적된 콘텐츠 가치 부족을 실질적으로 보완하되, 승인 자체를 보장한다고 표현하지 않는다.

## 범위

### 추가하는 화면

- `/guides`: 가이드 소개와 글 3개를 보여주는 목록
- `/guides/four-axes`: 개미타입의 4가지 판단 축 읽는 법
- `/guides/reading-results`: 4글자 코드와 16타입 이해하기
- `/guides/decision-journal`: 판단 습관을 한 줄로 기록하는 법

### 제외하는 기능

- 블로그 CMS, 관리자, 검색, 카테고리, 태그, 페이지네이션
- 16개 타입별 가이드 자동 생성
- 시황, 종목, 금융상품, 투자 전략 콘텐츠
- 가이드 페이지 내 광고 슬롯

## 콘텐츠 원칙

- 기존 `/about` 문장을 늘여 쓰지 않고, 사례·해석 경계·자기점검 질문처럼 새로운 정보를 제공한다.
- 축과 타입은 능력, 전문성, 투자 실력 또는 미래 성과를 평가하지 않는다.
- 모든 설명은 현재 20개 답변에서 자주 나타난 반응을 요약한다는 범위를 유지한다.
- `A/P`는 준비 후 시작하는 방식과 움직이며 조정하는 방식의 차이로 설명한다.
- `L/T`는 긴 흐름과 현재 구간 중 어디를 먼저 보는지의 차이로 설명한다.
- `R/I`는 기존 기준과 새 신호 중 판단의 출발점 차이로 설명한다.
- `D/C`는 확인 가능한 근거와 전체 맥락 중 확신을 얻는 방식의 차이로 설명한다.
- 각 축의 `3:2`, `4:1`, `5:0`은 응답 분포이며 확률, 정확도 또는 전문성 점수가 아니다.
- 정상적으로 20문항을 완료하면 각 축에 5개 응답이 있으므로 동점이 발생하지 않는다.
- 결과는 심리검사, 위험성향 진단, 투자 적합성 평가가 아니다.

## 금지 표현

- 추천 종목, 맞춤 포트폴리오, 매수·매도 타이밍
- 수익률을 높이는 법, 손실을 피하는 법, 안전한 투자
- 성공하는 타입, 위험한 타입, 최고의 타입
- 특정 타입에 유리한 투자 방식이나 금융상품
- 전문가가 검증했다는 근거 없는 권위 표현

## 글별 구성

### 1. 개미타입의 4가지 판단 축 읽는 법

- 4글자가 능력 평가가 아니라는 설명
- 네 축의 공식 정의와 일상적인 판단 사례
- 양쪽 반응이 각각 편해지는 상황과 부담이 되는 상황
- 결과 분포를 읽는 방법
- `T=단타`, `L=장기투자`, `D=분석`, `C=감 투자`로 단순화하면 안 되는 이유
- 관련 행동: 테스트 시작, 16타입 이해 가이드로 이동

### 2. 4글자 코드와 16타입 이해하기

- 코드 순서: 준비 방식, 시간 시야, 판단 기준, 확신 방식
- `ALRD`를 이용한 네 글자 해석 예시
- 한 글자만 다른 타입을 비교하는 방법
- 강점·습관·주의점을 단정이 아닌 자기점검 질문으로 읽는 방법
- 타입 간 우열과 성과 순위가 없다는 안내
- 관련 행동: 테스트 시작, 판단 기록 가이드로 이동

### 3. 판단 습관을 한 줄로 기록하는 법

- 결과를 투자 행동 지침이 아닌 관찰 출발점으로 사용하는 방법
- `무엇을 먼저 봤는지`, `왜 마음이 움직였는지`, `다시 본다면 무엇을 확인할지`를 적는 3문장 기록
- 최근 상황과 경험에 따라 결과가 달라질 수 있다는 설명
- 공유 결과에는 답변 분포가 없으므로 타입 기본 설명만 제공한다는 안내
- 관련 행동: 테스트 시작, 4축 가이드로 이동

## 정보 구조와 내부 연결

- 전역 헤더의 중복 `홈` 링크를 `가이드`로 교체한다. 로고는 계속 홈으로 연결한다.
- 푸터에 `가이드` 링크를 추가한다.
- 홈의 기존 안내 블록에 `/guides` 텍스트 링크를 추가하며 새 섹션은 만들지 않는다.
- 소개 페이지의 4축 설명에서 `/guides/four-axes`로 연결한다.
- 결과 페이지에는 결과 해석을 방해하지 않는 위치에 `/guides/reading-results` 링크 하나만 추가한다.
- 각 가이드 글 하단에는 관련 글 하나와 테스트 시작 링크만 둔다.
- 퀴즈와 계산 화면에는 가이드 링크를 추가하지 않는다.

## 구현 구조

- `src/data/guides.mts`: 가이드 슬러그, 제목, 요약, 순서의 단일 목록
- `src/components/guides/guide-layout.tsx`: 공통 글 머리말, 안전 고지, 관련 링크, CTA 레이아웃
- `src/app/guides/page.tsx`: 가이드 목록
- 각 가이드 경로의 `page.tsx`: 고유 메타데이터와 본문
- `src/app/sitemap.ts`: 목록과 상세 가이드 URL 추가
- 기존 홈, 소개, 결과, 헤더, 푸터에는 최소 내부 링크만 추가

가이드 콘텐츠는 정적 코드로 관리하며 별도 CMS나 런타임 데이터 요청을 추가하지 않는다.

## 메타데이터와 색인

- 네 페이지 모두 고유한 `title`, `description`, H1을 가진다.
- canonical은 Next.js의 `metadata.alternates.canonical`로 명시한다.
- 완성된 네 페이지를 사이트맵에 포함한다.
- 초안 상태의 URL은 공개하거나 사이트맵에 넣지 않는다.

## 테스트와 검증

### 자동 검증

- 가이드 목록이 정확히 3개인지 검증한다.
- 각 슬러그, 제목, 설명이 비어 있지 않고 중복되지 않는지 검증한다.
- `npm test`, `npm run lint`, `npm run build`가 통과해야 한다.

### 수동 검증

- `/guides`와 세 상세 URL이 모두 `200`으로 열린다.
- 홈·소개·결과·헤더·푸터에서 의도한 링크로 이동한다.
- 모바일에서 본문 폭, 문단 길이, 카드 터치 영역이 읽기 쉽다.
- 소개 페이지와 결과 페이지를 단순 반복한 문단이 없는지 확인한다.
- 투자 행동, 수익, 종목 또는 성과를 권하는 문장이 없는지 확인한다.
- 광고나 CTA가 본문 일부로 오해되지 않는지 확인한다.

## 문서 업데이트

- `README.md`의 구현 범위, 라우트, 배포 확인 항목에 가이드 경로를 반영한다.
- `docs/planning/ia.md`에 가이드 정보 구조를 반영한다.
- `docs/planning/ads-monetization-plan.md`에 콘텐츠 보강 상태를 반영한다.

## 성공 기준

- 사용자가 타입 코드와 네 축을 결과 페이지보다 더 깊게 이해할 수 있다.
- 가이드가 결과를 투자 조언으로 확장하지 않고 자기이해와 기록에 머문다.
- 기존 테스트 시작 흐름과 결과 공유 흐름이 변하지 않는다.
- AdSense 심사에 제출할 수 있는 독창적 정보성 콘텐츠가 늘어나지만 승인 보장을 주장하지 않는다.

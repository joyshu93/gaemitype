# 공개 사이트 독립 AI 콘텐츠 검토와 개선안

검토일: 2026-10-30 KST. 대상: [개미타입 운영 사이트](https://gaemitype.vercel.app/). 사용자 요청은 기획 배경을 제공하지 않은 독립 AI의 실제 사이트 검토와 구체적인 개선안 정리다. 이번 산출물은 검토·제안이며 제품 적용이나 배포 완료를 의미하지 않는다.

후속 상태: 이후 사용자가 C1의 Q5·Q6, C2·C3 및 B1의 적용·검증을 승인했다. 최신 작업트리에 로컬 적용과 검증을 마쳤으며 [구현 검증 기록](2026-10-30-content-implementation-verification.md)을 따른다. 운영에는 아직 반영하지 않았다. 아래 검토·미적용 서술은 최초 독립 평가 당시의 이력으로 보존한다. C4·C5의 추가 제안은 적용하지 않았다.

## 결론

세 검토자는 모두 계산 설명과 자기성찰 가이드의 기존 가치를 인정했고, **문항이 묻는 내용과 결과 축의 의미가 어긋나 보이는 부분을 최우선 개선 대상**으로 지목했다. 특히 Q5와 Q6가 반복해서 지적됐다. 결과의 분량 확대보다 질문→집계→설명으로 이어지는 연결의 납득을 강화하는 편이 우선이다.

권장 순서는 **① Q5·Q6 문항 의미 정리 ② 실제 답변을 연결하는 회고 문단 ③ 맞지 않는 결과를 보류하는 안내**다. 제작 기준 공개, 고지 중복과 탐색 경로는 그 다음으로 다룬다. 별도로 완주 직후 문서 제목 불일치를 재현했다.

## 독립성 및 확인 방법

- `fork_turns=none`으로 새 컨텍스트 세 개를 만들었다. URL과 역할별 일반 검토 과제만 제공했다. 기획 문서, 이전 대화, 심사 반려 이력, 구현 의도, 이전 검토 결론은 제공하지 않았다.
- 검토자는 저장소·소스·README·AGENTS·이전 기록과 다른 검토자의 결론을 읽지 않도록 지시받았고 미열람을 확인했다. 필요한 도구 사용 안내는 읽을 수 있었다.
- PM/UX는 공개 HTTP 본문과 실제 브라우저를 사용했다. 가상 입력으로 20문항을 완주했다. 기술/타입 구조와 QA/카피는 공개 HTTP HTML에서 script/style을 제외한 본문과 링크를 읽었고, 완주·클립보드 실행을 주장하지 않았다.
- 세 검토자가 최초 독립 결론을 낸 뒤 고정했다. 이후 메인이 작성한 문항·회고·반례 안내 초안을 관련 역할에 재검토시켰다. 이 후속 초안 검토는 최초 독립 평가와 구분한다.
- 메인은 기획을 아는 통합자다. 공개 브라우저에서 별도로 20문항을 진행하고 지적된 원문·결과를 확인했다. 메인의 판단을 독립 검토자의 첫 반응으로 표현하지 않는다.
- 컨텍스트 독립성은 확보했지만 서로 다른 모델이나 실제 사람을 대상으로 한 실험은 아니다. AI가 예상한 독자 영향과 직접 관찰한 텍스트·화면을 구분한다. AI 평가로 콘텐츠의 의미와 일관성을 검토할 수 있으며 실제 이용자 모집을 후속 작업의 선행 조건으로 두지 않는다.

PM/UX는 질문 진행 화면과 [가상 응답 ATRC 결과](https://gaemitype.vercel.app/result?code=ATRC&answers=01010101010101010101&source=answers)도 실제 조작했다. 메인은 가상 입력 `01010010100101001010`(ALRD)과 `01010101010101010101`(ATRC)을 공개 질문 UI로 각각 완주했다. 응답 패턴은 테스트용이며 실제 개인의 성향 자료가 아니다. 독립 콘텐츠 비교의 표본은 주로 ALRD·ALRC이므로 16타입 전부의 고유 가치를 평가한 것처럼 일반화하지 않는다.

## 유지할 기존 가치

1. 홈은 20문항, 로그인 없는 시작, 결과 예시와 공유를 명확히 안내한다.
2. 결과 읽기 가이드는 가상 20개 답변→축별 합산→코드와 같은 코드의 3:2·5:0 차이를 공개한다. 계산 과정을 모호하게 감추지 않는다.
3. 개인 결과의 실제 선택 사례와 타입 공통 장면을 구분하며, 판단 기록 가이드는 세 줄 기록이라는 실제 활용 방법을 제공한다.

따라서 가이드가 전혀 없거나 실제 답변 근거가 없는 서비스로 취급해 같은 내용을 다시 추가하지 않는다.

## 발견 사항과 구체적 개선안

### C1. 질문과 축의 연결이 약한 문항 — 우선

**직접 관찰:** Q5는 카페에서 ‘내가 원래 좋아하는 메뉴부터 먼저 찾는다 / 새로운 인기 메뉴부터 본다’를 묻는다. 결과 읽기 가이드의 전체 원문과 집계 표는 Q1–Q5를 A/P 준비 방식에 연결한다. 그런데 네 축 가이드의 A/P는 미리 정리 / 현장에서 정하기이며, 기존 기준 / 새 정보는 별도 R/I 축이다. Q15도 기존 취향과 화제 정보에 대한 반응을 묻는다.

Q6는 ‘그 채널의 다른 영상을 섭렵한다 / 더 재밌는 채널이 없는지 찾아본다’를 L/T에 연결한다. 공개 L/T 정의는 긴 흐름 / 지금 구간의 조정이다. 현재 선택지는 관심의 깊이 또는 새로움 선호로도 읽힌다.

**판단:** 계산이 맞아도 그 답이 왜 그 축의 단서인지 납득하기 어렵다. 세 역할이 독립적으로 같은 문제를 지적했다. 이는 공개 문안의 의미상 중첩에 대한 판단이며, 검사 정확도가 낮다는 측정 결과는 아니다.

**개선 초안:** 기존 일상 소재를 유지하면서 대비하는 요소를 좁힌다.

| 문항 | 질문 초안 | 첫 선택 | 둘째 선택 |
|---|---|---|---|
| Q5 | 처음 가는 카페를 정했어요. 메뉴를 고르는 모습에 더 가까운 쪽은? | 가기 전에 메뉴판을 살펴보고 마실 것을 정해둔다 | 도착한 뒤 메뉴판을 살펴보고 마실 것을 정한다 |
| Q6 | 보던 영상 시리즈의 업로드 일정이 바뀌었어요. 무엇을 먼저 살펴보나요? | 앞으로 몇 주 동안 보는 흐름에 미칠 영향을 본다 | 오늘 보는 데 바로 조정할 부분을 본다 |

Q5는 PM/UX가 익숙함·새로움 혼합을 줄이고 방문 전/현장 차이에 직접 연결된다고 검토했다. 다만 메뉴 사전 공개 여부 같은 상황 영향은 남는다. Q6는 기술/타입 검토자의 후속 제안으로, ‘일정·순서’ 대비를 줄이고 시간 범위를 드러냈다. 초안의 의미상 개선을 심리적 타당성 검증으로 표현하지 않는다.

**적용 범위 제안:** 먼저 Q5·Q6를 확정하고 전체 20문항도 같은 기준으로 대조한다. 설명을 덧붙여 모호한 문항을 억지로 정당화하지 않는다. 실제로 문항을 바꿀 경우 문항·축 매핑·가이드의 가상 원문과 사례를 함께 맞춘다. 점수 규칙이나 축별 다섯 문항 구조 변경까지 자동 확대하지 않는다.

**완료 기준:** 축명을 가린 문항을 독립 AI가 공개 축 정의에 다시 연결하고 근거를 설명할 수 있다. 다른 축에도 자연스럽게 연결되는 문항은 혼동 이유를 남겨 다시 편집한다. 문항 수·집계·가이드 원문 일치도 검증한다. 이는 AI를 이용한 편집 기준이며 실제 반응에 대한 수치 검증은 아니다.

### C2. 실제 답변의 차이를 돌아보는 연결 설명 — 우선

**직접 관찰:** 개인 결과에는 실제 선택 예시와 분포가 이미 있고, 그 아래 공통 장면과 공통 회고 질문이 이어진다. ALRD·ALRC 비교에서는 상당 부분을 공유하고 마지막 축이 달라진다.

**판단:** 축의 정의를 익힌 뒤 추가로 얻는 해석이 반복으로 느껴질 수 있다. 이 영향은 AI의 편집 판단이다. PM은 축 조합의 고유 장면을, QA와 기술/타입 검토자는 실제 차이를 보여주는 비교를 제안했다.

**통합 제안:** 별도 성격 특성을 만들어내는 조합 서사보다 **현재 답변에서 확인되는 두 선택을 연결하는 회고 문단**을 먼저 사용한다. 기존 선택 예시 근처에 짧게 배치하고, 동일한 공통 질문을 더 추가하는 방식은 피한다.

ALRD 테스트 입력의 실제 선택에 기반한 초안:

> 맛집을 정할 때는 ‘후기와 메뉴를 먼저 검색해본다’를, 짧은 나들이에서는 ‘일단 출발하고 가는 길에 하나씩 정한다’를 골랐어요. 두 장면에서 먼저 고른 방식이 달랐던 이유가 떠오르나요?

초안 첫 버전의 ‘미리 확인할 필요를 다르게 느꼈다’는 표현은 이용자의 이유를 추정하므로 제외했다. PM/UX와 기술/타입 역할은 수정 방향이 기존 예시 나열을 실제 회고로 이어주는 가치가 있다고 검토했다.

**표시 조건과 완료 기준:**

- 3:2·4:1 등 양방향 선택이 있을 때만 해당 축에서 실제로 고른 서로 다른 방향의 선택을 연결한다.
- 5:0에서는 실제 선택 한 개와 열린 회고 질문을 사용한다. 반대 선택이나 선택 이유를 만들지 않는다.
- 코드 전용·잘못된 answers에는 개인 답변 서술을 표시하지 않는다. 공유 문구에도 개인 사례를 담지 않는다.
- 문항의 실제 문구와 선택 의미를 유지한다. 타입 코드만으로 답변이나 이유를 역추정하지 않는다.
- 기존 예시 바로 옆에서 간결하게 읽히며 개인 모드·코드 전용·답변 확인 실패 분기가 유지되는지 검증한다.

정적 문안과 현재 응답을 조합하는 범위로 설계할 수 있다. 새 계정·DB·실시간 AI 생성 기능은 이 제안에 필요하지 않다.

### C3. 맞지 않는 결과를 보류할 수 있는 안내 — 작고 우선할 편집

**직접 관찰:** 판단 기록 가이드에는 ‘맞지 않는 장면도 그대로 기록할 만한 정보예요’ 뒤에 ‘반대 방향의 단서를 쓴 순간이 있었다고 해서 결과가 잘못된 것은 아닙니다’가 이어진다.

**판단:** 반례를 적게 하는 장점은 있지만, 다른 경험이 나와도 결과를 계속 옹호하는 문장으로 읽힐 수 있다. QA의 독립 지적이며 발생 빈도를 측정한 것은 아니다.

**교체 초안:** 해당 단락의 마지막 두 문장을 다음 두 문장으로 교체한다.

> 설명이 잘 맞지 않으면 타입을 보류해도 괜찮아요. 맞는 장면과 맞지 않는 장면을 하나씩 적고, 도움이 된 부분만 가져가세요.

QA가 본문 취지와 이용자 판단권을 유지한다고 재검토했다. 계산 결과가 사라진다는 의미로 읽히지 않도록 여기서 보류하는 것은 설명을 받아들이는 판단이라는 맥락을 유지한다.

**완료 기준:** 반례를 결과의 정당화로 자동 회수하지 않고, 이용자가 설명을 받아들이지 않을 선택도 자연스럽게 읽힌다. 이를 위해 새 입력 기능은 필요하지 않다.

### C4. 제작 기준·근거 수준의 설명 — 사실 확인 후

**직접 관찰:** 소개는 각 축 다섯 문항·다수 선택·코드 조합을 설명한다. 공개 본문에서는 축 선정 이유, 문항 작성·검토 원칙, 신뢰도·타당도 검증 수행 여부를 확인할 수 없었다.

**제안:** 기존 ‘결과는 어떻게 만들어지나요?’ 뒤에 확인된 제작 기준과 검증 범위를 짧게 보완한다. 실제 수행한 검토만 기재하고 미공개를 미실시로 단정하지 않는다. 제작자·전문가·연구 이력을 발명하지 않는다.

현재 공개 내용으로 지지되는 예시 문장:

> 선택 횟수의 합산은 이번 응답을 요약하는 계산 방식이며, 그 자체로 검사 정확도나 미래 행동의 예측력을 뜻하지 않습니다.

이 문장은 기존 한계 안내와 겹치므로 단독으로 추가하기보다 실제 제작 기준의 사실 확인을 먼저 해야 한다. 단순 면책 반복을 새로운 콘텐츠 가치로 계산하지 않는다.

### C5. 반복 고지·결과 탐색 — 후순위 정리

- PM/UX와 QA는 일상 테스트에 투자 관련 제한이 여러 번 나와 정체성을 흐릴 수 있다고 판단했다. 홈 본문·가이드 하단·공통 푸터의 역할을 대조하고 필요한 안내는 명료하게 유지하면서 인접한 중복을 줄이는 편집을 검토한다. 금지 표현이나 안전 안내를 전면 삭제하는 제안은 채택하지 않는다.
- 소개에는 이미 개미 캐릭터와 타입 이름이 재미를 위한 표현이라는 안내가 있다. 이 설명이 없다는 전제로 새 단락을 만들지 않는다.
- 기술/타입 역할은 16타입의 공개 탐색 경로가 ALRD·ALRC에 편중됐다고 지적했다. 기존 결과 링크를 모으거나 한 글자 다른 이웃 타입으로 이동하는 정적 링크가 대안이다. 이는 접근성을 높이는 개선이며 본문 내용의 독창성 자체를 자동으로 늘리지는 않는다.
- 우선순위는 C1–C3 뒤다. 긴 설명을 접거나 공유 버튼을 앞당기는 편집도 핵심 안내와 실제 답변 근거의 가시성을 유지하는 범위에서 검토한다.

## 별도 발견 B1: 완주 직후 결과 제목 불일치

PM/UX의 첫 보고는 도구의 탭 제목·접근성 결과 관찰이었다. 후속 확인에서 `document.title`을 직접 읽은 것이 아니므로 그 보고만으로 문서 결함을 확정하지 않는다고 정정했다.

메인이 별도 공개 브라우저에서 `01010101010101010101`을 실제 질문 UI로 완주해 보완 확인했다.

| 항목 | 완주 직후 관찰 |
|---|---|
| URL | `/result?code=ATRC&answers=01010101010101010101&source=answers` |
| 본문 h1 | 상황가늠형 |
| DOM `document.title` | 기준설계형 (ALRD) \| 개미타입 |
| 같은 URL 새로고침 뒤 | 본문과 제목 모두 상황가늠형 (ATRC)으로 일치 |

따라서 완주 경로에서 실제 문서 제목 불일치를 한 번 재현했다. 다른 브라우저·경로의 발생 범위와 코드 원인은 조사하지 않았다. 제안은 완주 경로의 메타데이터 갱신을 조사하고 URL·본문·제목이 일치하도록 고치는 것이다. 새로고침이 필요 없는지와 직접 진입도 검증해야 한다. 이는 콘텐츠 가치와 별도의 정확성 문제이며 심사 반려 원인으로 단정하지 않는다. 이번에는 수정하지 않았다.

## 역할별 합의와 충돌 처리

| 역할 | 최초 독립 평가 핵심 | 통합 반영 |
|---|---|---|
| PM/UX | 질문–축 연결, 조합 결과의 추가 발견, 결과 정보 순서, 제목 불일치 | C1·C2·C5·B1. 공개 가이드의 기존 가치도 유지 |
| 기술/타입 | 질문–축 연결, 제작 기준, 16타입 탐색 | C1·C4·C5. 인접 타입 비교와 근거 수준을 강조 |
| QA/카피 | 질문–축 연결, 이름 대비 해석 폭, 반례 수용, 반복 고지 | C1·C2·C3·C5. 금지 약속을 추가하지 않음 |

공통 문장을 유지할지 타입별 서사를 늘릴지에 차이가 있었다. 제품 원칙 → MVP 범위 → 구현 복잡도 순으로 판단해, 근거 없는 교차축 성격 이야기는 채택하지 않고 **실제 답변 연결과 반례 허용**을 우선했다. 비교표·링크·고지 압축은 본문의 실질적 보완과 구분했다.

## QA와 후속 검증

- **오해 가능성:** 문항의 의미가 모호한 상태에서 계산 투명성을 타당성으로 읽는 것, 공통 장면을 실제 답변으로 읽는 것, 결과와 다른 경험을 무조건 결과에 끼워 맞추는 것, 독립 AI 세 건을 실제 이용자 검증으로 읽는 것.
- **금지 표현:** 정확한 성격·투자 능력 진단, 실제 응답에 없는 선택·원인 서술, 수익·위험 회피 보장, 검증하지 않은 과학적 정확도·전문가 검증, 특정 편집으로 심사 승인 보장.
- **수동 검증:** 실제폰에서 문항과 결과의 가독성, 개인/코드 전용/답변 확인 실패, 혼합/한쪽 응답, 공유 후 개인 사례 제외, 완주 후 제목 일치. 이번은 데스크톱 브라우저의 가상 완주이며 실제 휴대폰·200% 확대·화면 읽기·외부 메신저 OG를 확인했다고 주장하지 않는다.

# 승인 콘텐츠와 결과 제목 수정 계획

사용자 승인: Q5·Q6, 개인 결과 회고, 결과 보류 안내, 제목 불일치 수정과 검증. 기준 HEAD `22341be`. 승인 사양은 [독립 검토 보고서](2026-10-30-blind-public-content-review.md) C1–C3 및 B1이다.

## 범위와 구현 결정

- 기존 `approved-experience` 격리 작업트리와 미커밋 문서를 보존한다. 이번 라운드는 로컬 구현·검증까지다.
- Q5·Q6의 id·배열 위치·축·옵션 value/code와 채점 규칙은 보존하고 승인 원고 및 보조문만 바꾼다. 가이드의 예시는 현재 질문에서 생성된다.
- 각 축의 기존 실제 예시 뒤에 Q번호·선택 원문을 연결한 열린 회고를 붙인다. 혼합 응답은 두 인용, 5:0은 한 인용, 예시 없음은 표시하지 않는다. 공유·잘못된 답변에는 개인 회고를 넣지 않는다.
- 판단 기록 가이드의 마지막 두 문장은 승인 인용문 그대로 교체한다. 보고서의 ‘세 문장’ 표기는 실제 두 문장인 인용문을 기준으로 정정한다.
- 문항 의미가 바뀌므로 새 답변은 `v=2`를 계산·개인 결과 URL에 전달한다. 버전 없는 이전 개인 링크는 Q5·Q6의 이전 원문으로 재현한다. 새 임시 저장 키를 사용해 구문항 응답의 자동 재사용을 방지한다. 공유 링크는 code만 유지한다.
- 제목은 query별 prefetch cache 충돌의 오염원인 결과 링크 네 곳에서 자동 prefetch를 비활성화하는 최소 수정부터 검증한다. DOM title 사후 덮어쓰기는 사용하지 않는다.

## 검증 초점

1. 회고 인용이 실제 선택에서만 나오고 같은 코드라도 답변 순서 차이를 반영하는가.
2. 5:0에서 반대 선택이나 선택 이유가 만들어지지 않는가.
3. 공유·중복/오류 answers·알 수 없는 문항 버전에서 개인 문단이 생기지 않는가.
4. 버전 없는 과거 링크는 과거 Q5·Q6를, 새 링크는 새 문항을 표시하는가. 공유에는 answers·v가 빠지는가.
5. 랜딩·가이드의 결과 링크가 보인 뒤 완주해도 URL·본문·문서 제목·OG·canonical이 일치하는가.

카피 변경에 소스 문자열 고정 테스트를 새로 만들지 않고 승인 원고를 일회성 대조한다. 회고·버전 분기에는 실제 입력/출력을 사용하는 회귀 테스트를 추가한다. 제목은 사전 로딩이 켜지는 실제 production 빌드 브라우저 경로로 RED→GREEN을 확인한다.

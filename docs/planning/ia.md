# IA

## 목표

개미타입의 핵심 흐름을 짧고 명확하게 유지하면서, 랜딩에서 결과 공유까지 끊기지 않는 사용자 경험을 만든다.

## 전체 구조

1. 랜딩 페이지
2. 질문 플로우 페이지
3. 계산/전환 상태
4. 결과 페이지
5. 공유 액션
6. 서비스 소개
7. 개인정보처리방침
8. 가이드 목록 (`/guides`)
9. 4가지 판단 축 가이드 (`/guides/four-axes`)
10. 4글자 코드와 16가지 결과 가이드 (`/guides/reading-results`)
11. 판단 습관 기록 가이드 (`/guides/decision-journal`)

- 공유 결과에 응답 분포가 포함되지 않는다는 안내
- 다음 관련 가이드 링크

## 사용자 흐름 원칙

- 랜딩에서 "무엇을 하는 서비스인지" 5초 안에 이해 가능해야 한다.
- 질문은 한 화면 1문항으로 고정한다.
- 선택 즉시 다음 문항으로 자동 진행한다. 마지막 선택 뒤에는 계산 화면으로 이동한다.
- 진행률은 항상 보이게 한다.
- 진행률은 `stepIndex / 20`으로 계산한다. `q01`은 `0%`, `q20`은 `95%`를 표시한다.
- 질문별 레이아웃은 통일한다.
- 결과 페이지는 점수 숫자보다 타입 정체성이 먼저 보이게 한다.
- 공유는 결과 확인 직후 가장 자연스럽게 노출한다.
- 헤더와 푸터는 모든 페이지에서 가이드 목록(`/guides`)으로 연결한다.
- 홈은 가이드 목록, 서비스 소개는 4가지 판단 축 가이드, 결과 페이지는 결과 읽기 가이드로 문맥에 맞게 연결한다.
- 질문과 계산 페이지에는 가이드 링크를 노출하지 않아 한 번에 하나의 행동만 요구한다.

## 질문 UX 원칙

- 질문 문장은 생활어 중심으로 짧게 쓴다.
- 금융 전문용어는 가능하면 피한다.
- 사용자가 정답을 찾으려 하지 않도록 가치판단 어휘를 줄인다.
- 초반 질문은 직관적이고 가벼운 문항으로 시작한다.
- 후반 질문은 미세한 차이를 가르는 문항을 배치한다.

## 결과 UX 원칙

- 상단 1스크린 안에 타입 정체성이 드러나야 한다.
- 4축은 막대그래프보다 카드형 요약을 우선 검토한다.
- 장점과 주의점은 행동 지시가 아니라 성향 해석 수준으로 제시한다.
- 고지 문구는 작게 숨기지 말고 자연스럽게 읽히는 위치에 둔다.

- 공유 문구 복사
- 다시 테스트하기

## 모바일 우선 기준

- CTA는 하단 엄지 영역에서 쉽게 누를 수 있어야 한다.
- 선택지는 스크롤 없이 한 화면에 들어오는 높이를 우선한다.
- 텍스트는 길어도 3줄 안팎에서 끊기도록 작성한다.
- 결과 페이지 첫 화면에 타입명과 한 줄 설명이 모두 보여야 한다.

## 결정 사항과 이유

- 질문은 1문항 1화면으로 간다.
  - 이유: 집중도와 모바일 가독성이 가장 안정적이다.
- 결과 상단에는 코드보다 별칭과 한 줄 설명을 더 강조한다.
  - 이유: 공유성과 이해성을 동시에 높인다.
- 공유는 결과 직후 링크 복사 우선으로 제공한다.
  - 이유: MVP 구현 비용 대비 효율이 높다.

## 현재 구현 상태

- 랜딩, 질문, 계산, 결과, 공유 액션의 단일 흐름이 구현되어 있다.
- 서비스 소개와 개인정보처리방침은 푸터에서 모든 페이지에 연결한다.
- 헤더와 푸터는 가이드 목록에 연결하고, 홈·서비스 소개·결과 페이지에는 문맥에 맞는 가이드 링크를 제공한다.
- 가이드 목록과 정확히 3개의 독자 가이드가 구현되어 있으며, 가이드는 서로 다음 관련 글로 연결한다.
- 질문과 계산 페이지에는 가이드 링크를 노출하지 않는다.
- 질문과 계산 페이지는 검색 색인에서 제외하고, 홈·소개·정책·16개 결과 URL을 sitemap으로 제공한다.
- sitemap은 가이드 목록과 3개 가이드 URL도 제공한다.
- 질문 카드는 한 화면에 한 문항과 두 선택지를 보여주며, 이전과 처음부터 동작을 제공한다.
- 결과 공유는 결과 링크와 타입별 공유 문구를 각각 클립보드에 복사한다.
- 공유 이미지 저장과 유형 비교 화면은 현재 제공하지 않는다.

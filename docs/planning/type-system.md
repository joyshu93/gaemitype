# Type System

## 목표

개미타입의 4축 16타입 구조를 일관되게 정의하고, 질문과 결과 카피가 같은 체계를 따르도록 만든다.

## 타입 시스템 원칙

- 각 축은 서로 다른 판단 차원을 다뤄야 한다.
- 좋은 타입과 나쁜 타입은 없다.
- 결과는 능력 평가가 아니라 행동 경향 설명이다.
- 타입명은 이해 가능성을 우선하고, 과도한 캐릭터화는 피한다.
- 결과 문구는 투자 조언처럼 읽히지 않아야 한다.

## 4축 정의

| 축 | 코드 | 해석 축명 | 설명 |
| --- | --- | --- | --- |
| 1 | A / P | 판단 준비 방식 | `A` 준비형: 움직이기 전에 기준과 흐름을 먼저 정리해두면 더 편안한 쪽. `P` 현장형: 상황을 보면서 그때그때 더 맞는 쪽으로 조정하는 편. |
| 2 | L / T | 보는 시간 길이 | `L` 흐름형: 짧은 흔들림보다 조금 더 긴 흐름과 방향을 보는 편. `T` 타이밍형: 지금 구간의 변화와 리듬을 빠르게 읽는 쪽에 가까움. |
| 3 | R / I | 판단을 움직이는 기준 | `R` 기준형: 내 기준과 원래 세운 규칙을 먼저 확인해야 마음이 놓이는 편. `I` 반응형: 새로 들어온 신호와 분위기 변화에 더 빠르게 반응하는 편. |
| 4 | D / C | 확신을 얻는 방식 | `D` 근거형: 숫자나 자료처럼 확인 가능한 근거가 있어야 더 확신이 생김. `C` 감각형: 전체 맥락과 감각이 맞아떨어질 때 더 확신이 붙음. |

## 코드 순서

타입 코드는 항상 아래 순서로 고정한다.

`판단 준비 방식 -> 보는 시간 길이 -> 판단을 움직이는 기준 -> 확신을 얻는 방식`

예시: `ALRD`

## 16타입 체계

| 코드 | 한글 별칭 | 핵심 설명 |
| --- | --- | --- |
| ALRD | 기준설계형 | 시작 전에 기준을 정리하고, 한 번 납득하면 오래 가져가는 편이에요. |
| ALRC | 원칙항해형 | 자기 기준을 지키면서도 전체 흐름을 차분히 읽는 편이에요. |
| ALID | 탐색축적형 | 새 정보에 귀를 기울이지만, 바로 결론 내리기보다 오래 쌓아보는 편이에요. |
| ALIC | 감각개척형 | 스스로 감이 온 방향이 있으면 묵직하게 밀고 가는 편이에요. |
| ATRD | 점검기동형 | 움직임은 빠르지만, 기준과 근거를 다시 확인하고 싶어 하는 편이에요. |
| ATRC | 타이밍포착형 | 흐름을 민감하게 읽고, 지금 들어갈지 말지 타이밍을 잘 살피는 편이에요. |
| ATID | 반전탐험형 | 남들이 지나친 포인트를 다시 보고, 낯선 방향도 열어두는 편이에요. |
| ATIC | 기회캐치형 | 분위기 변화에 빠르게 반응하고, 기회가 보이면 몸이 먼저 움직이는 편이에요. |
| PLRD | 흐름추적형 | 큰 흐름을 따라가되, 안에서 기준을 놓치지 않으려는 편이에요. |
| PLRC | 집중추세형 | 흐름이 잡히면 흔들리기보다 한 방향으로 힘을 싣는 편이에요. |
| PLID | 낙관추종형 | 분위기가 좋다고 느끼면 오래 따라가며 자연스럽게 리듬을 타는 편이에요. |
| PLIC | 직진불도저형 | 확신이 생기면 망설이기보다 묵직하게 앞으로 나아가는 편이에요. |
| PTRD | 민첩조정형 | 흐름이 바뀌는 걸 빨리 보고, 그에 맞게 판단을 조정하는 편이에요. |
| PTRC | 모멘텀승부형 | 리듬이 살아날 때 힘을 싣는 데 익숙하고, 속도감 있는 전개를 좋아하는 편이에요. |
| PTID | 유연탑승형 | 상황 변화를 가볍게 받아들이고, 자연스럽게 방향을 바꾸는 편이에요. |
| PTIC | 순간헌터형 | 분위기와 타이밍 변화에 가장 민감하게 반응하는 편이에요. |

## 타입 결과 공통 포맷

- 4글자 코드
- 한글 별칭
- 핵심 한 줄 설명
- 왜 이런 타입인지 설명
- 강점 3개
- 주의점 2개
- 성향 참고용 안내 문구

## 축별 강점 표현 가이드

- A: 준비가 빠르다, 기준을 세운다
- P: 변화에 유연하다, 상황 적응이 빠르다
- L: 긴 호흡을 유지한다, 흔들림에 둔감하다
- T: 반응 속도가 빠르다, 짧은 구간 변화에 민감하다
- R: 룰을 잘 지킨다, 자기 기준이 분명하다
- I: 새 흐름을 잘 포착한다, 변화 감지가 빠르다
- D: 숫자와 자료를 꼼꼼히 본다
- C: 분위기와 맥락을 넓게 읽는다

## 축별 주의점 표현 가이드

- A: 준비에 시간이 오래 걸릴 수 있다
- P: 기준이 자주 바뀔 수 있다
- L: 대응 속도가 늦어질 수 있다
- T: 잦은 판단 전환으로 피로가 생길 수 있다
- R: 새로운 흐름을 늦게 받아들일 수 있다
- I: 순간 이슈에 흔들릴 수 있다
- D: 과도한 확인으로 결정이 늦어질 수 있다
- C: 느낌이 근거보다 앞설 수 있다

## 점수 계산 원칙

- 축당 5문항을 배치한다.
- 각 문항은 한 축만 측정한다.
- 응답은 양극 선택으로 설계한다.
- 축별 다수값으로 최종 코드를 결정한다.
- 정상 완주에서는 축마다 5문항에 모두 답하므로 합계가 홀수다. 따라서 축별 동점은 발생하지 않는다.

## 불완전 응답과 URL 복원

- 정상 퀴즈 플로우는 20개 응답을 모두 받은 뒤에만 점수를 계산한다.
- URL에 직렬화된 답변이 없거나 불완전하거나 결과 코드와 맞지 않으면, 코드는 해당 답변으로 결과를 계산하지 않는다. 대신 URL의 유효한 4글자 타입 코드로 공유 결과를 복원한다.
- 이는 공유 링크를 다시 열기 위한 fallback이며, 정상 완주 시의 축 판정 또는 동점 규칙이 아니다.

## 결정 사항과 이유

- `D/C` 축은 분산/집중 대신 데이터/맥락으로 재정의한다.
  - 이유: 기존 `D/C = Diversified/Concentrated`는 실제 행동 추천처럼 읽힐 위험이 있고, 다른 축과 겹칠 여지가 있다.
- 타입명은 설명형을 우선 채택한다.
  - 이유: 첫 MVP에서는 공유보다 이해성과 안전성이 더 중요하다.
- 축 표기는 유지하되, 사용자에게 보이는 축 이름은 투자 행동 장면이 떠오르도록 보정한다.
  - 이유: 구조를 바꾸지 않고도 일반 성격검사처럼 보이는 인상을 줄일 수 있다.

## 현재 결정 사항

- 16개 타입명과 핵심 설명은 현재 `type-profiles.ts`의 정적 데이터와 동일하게 유지한다.
- 응답 기반 결과 모드는 실제 답변으로 계산한 축별 응답 비율과 선택된 성향 요약을 함께 제공한다.
- 타입 코드만 있는 공유 결과 모드는 신뢰할 수 없는 강도나 점수를 만들지 않고, 각 축에서 선택된 성향 요약만 제공한다.
